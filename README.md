# CNHS Portal v2 (Flutter + Node + Supabase)

```
app/       Flutter: Android (students, teachers, parents) + Windows (teachers, USB sync)
backend/   Node.js API on Render (writes, IDs, biometric parsing, class records, push)
backend/sql/001_schema.sql -> 002_ids.sql -> 003_classrecords.sql -> 004_subjects_storage.sql -> 005_profile.sql -> 006_classes.sql -> 007_realtime_requests.sql -> 008_reminders.sql -> 009_noclass_autoabsent.sql -> 010_sync_ops.sql -> 011_feed.sql -> 012_student_subjects.sql -> 013_mock_data.sql (optional test data)   run in this order in the Supabase SQL editor
```
The `android/` and `windows/` projects are **generated by the GitHub workflow** (`flutter create` + `app/tool/patch_platforms.py`), so you never commit them.

## Setup
1. **Supabase**: run the twelve SQL files (004 fixes photo upload and adds typed teacher subjects). Auth > Providers > Google (client ID/secret from Google Cloud).
   Auth > URL Configuration > Redirect URLs, add BOTH:
   `io.cnhs.portal://login-callback` (Android) and `http://localhost:54321/callback` (Windows sign-in).
2. **Render**: new Web Service from the repo (`render.yaml`). Env: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, optional `FCM_SERVICE_ACCOUNT_JSON`.
3. **GitHub > Settings > Secrets > Actions**: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `API_URL` (Render URL).
   Phone push (optional; leave empty to build without it): `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_SENDER_ID`, `FIREBASE_PROJECT_ID`
   (Firebase console > Project settings > your Android app `io.cnhs.cnhs_portal`). No google-services.json needed.
4. Push to `main`. Actions builds `cnhs-android-apk` and `cnhs-windows` (zip). If a build fails, open the step named **Analyze**: it lists each Dart error with file and line.

## Biometric USB
- Recognised files, with spaces OR underscores: `Attendance Logs*.txt` (every one found is uploaded; repeats are ignored), `Employee Form*.xls`, `001_UserInfo.dat` (detected only, never edited: fingerprint templates).
- Plug in -> logs uploaded -> punches stored -> students + approved parents notified (in-app realtime + phone push).
  First punch = time in; last punch counts as time out only if 30+ min later. Late = more than 15 min after the section's first class.
- Absent: days before the newest punched day are closed automatically after a sync. **Newest day (today): 30 minutes after a sync, every student with no punch is marked Absent and parents are notified.** Safeguards: only sections whose first class had already started when the USB was read are closed, the day needs at least one punch in the file, and a later sync re-opens the day (a late punch replaces the absent mark). Needs the minute cron below (or the server awake).
- App changes (students, sections, schedules) rewrite `Employee Form.xls` on the stick; the original is kept once as `Employee Form.xls.bak`. People already on the terminal are kept in the file.
- **Device ID vs Student ID**: the school Student ID (`202627-48213`) is separate from the terminal's device ID. New students get a device ID above every ID the terminal already uses. For people already enrolled on the terminal, open the student in the advisory list and tap the fingerprint icon to link their existing device ID; their old punches are attached automatically.

## Teacher tools (ported from the PHP portal)
- **My classes** (subjects the adviser assigned to you): Class record (columns, scores, weighted percent, copy to term grade with 60->75 transmutation), Attendance per subject (P/A/L/E by date, allowed absences, warning at 80%, over-limit can mark Dropped), Grades (release/unrelease, notifies students and parents).
- **Advisory**: students, schedule (assigns subject teachers), Homeroom attendance (manual marking over/alongside the fingerprint data).
- **Add class** (My classes > Add class): any teacher can create a class in any section, advisory or not. Choose grade level (from your profile), one of your subjects, the section (an existing section with that name is picked automatically, otherwise it is created) and a room, then set the schedule (days + times). The server refuses a class if the teacher or the section already has something at that time, or if another teacher already teaches that subject in that section. Inside a class you get Students, Class record, Attendance, Grades and Schedule.

## Classes (teachers)
- **My classes -> Add class**: grade level (from your profile), one of your subjects (from the Subjects tab), a section **or room**, a room for the class, and a schedule (Mon-Fri, one or more time blocks).
  If the section name or room already exists for that grade (under anyone's advisory) it is picked automatically; otherwise a new section is created (without an adviser until someone taps **Become adviser**).
- A subject can have only one teacher per section; a teacher cannot be booked in two places at once, and a section cannot have two classes at the same time.
- Each class opens with **Students** (live roster, search, details, absences in this subject), **Class record**, **Attendance**, **Grades** and **Schedule**.
- Desktop/tablet (wide window): classes on the left, the open class on the right. Phones: a list that opens each class.
- Removing a class only removes the assignment and its schedule; grades, attendance and class-record data stay saved.
- **Biometric IDs belong to students only.** Teachers have none. People on the terminal who are not students can be ignored in the USB tab.

## Navigation and live updates
- **Students and parents (Android)**: hamburger menu. Parents get one entry per linked child. **Sign out is at the bottom of the Profile screen** for everyone.
- **Teachers**: detailed bottom bar on phones (icons, labels, counters for new requests and unread alerts); navigation rail on Windows.
- Screens are created on first open and then kept alive, and lists are live (Supabase Realtime), so switching screens does not reload them. Run `007_realtime_requests.sql` so every table is part of the realtime publication.

## Home, advisory and class reminders (teachers)
- **Home** is the first tab: your photo, name and Teacher ID, your weekly schedule (List or Week calendar, each block shows subject, grade and section) and the **approaching class** with a live countdown.
- **Classes** now holds everything: amber **advisory** cards (section first) and subject-class cards (section first, subject beneath). In **Add class** tick *I'm the adviser of this section* (only possible when the section has no adviser or you already are); tick *I only advise this section* if you teach no subject there.
  When you are the adviser, a subject class also gets the **Homeroom** tab and the student tools (add by ID, edit address, link device ID, remove).
- **Phone reminders**: choose Off / 5 / 10 / 15 / 20 / 30 / 45 / 60 minutes before class on the Home tab. The server sends "Mathematics starts in 10 min" as a push notification (Android).
  Render's free plan sleeps, so add a free 1-minute cron job (for example on cron-job.org) that opens
  `https://YOUR-API.onrender.com/cron/class-reminders?key=YOUR_CRON_SECRET`
  and set the same `CRON_SECRET` in Render. The call is safe to repeat: each class is announced once per day. Needs the Firebase secrets from the setup section for push.


## Students and parents (Android)
- Bottom bar like the teacher app: **Home, Attendance, Grades, Alerts, Profile**. Parents with several children get a child switcher above the tabs; the top-right button links another child.
- **Home**: photo, name and Student ID, then the weekly schedule (List / Week), today's attendance card and the approaching class with a live countdown. Cancelled classes show **No class**.
- **Attendance**: summary ring, month calendar (tap a day for time in/out), and a dated list. **View attendance by subject** (students and parents) shows today's status in every class, and per-subject totals, rate and history.
- **Grades**: laid out like a printed report card (learning areas x Q1-Q4, final, remarks, general average, honors, grading scale).
- Subject teachers keep the last word: a student auto-marked absent at the gate can still be marked Present / Absent / Late / Excused in each subject (the attendance grid shows the gate record as a dot, and a **Gate** shortcut copies it). Marking a student absent/late/excused in a subject notifies the student and parents.

## No-class alerts (teachers: Alerts > No class)
Pick the day, subject, and which grade levels / sections are affected (or **Send to all**). Students and parents are notified, every student's subject attendance for that day becomes **No class** (never absent), and the schedule shows it. Future dates are applied on the day itself. **Resume class** undoes a notice and tells everyone.
Run `009_noclass_autoabsent.sql` (adds the N status, notices table, auto-absent table, and a `kid_photos` view so parents see their child's photo).
The existing 1-minute cron URL (`/cron/class-reminders?key=...`) now also closes absences and applies no-class marks.

## Offline mode (students, parents, teachers)
- The app remembers who was signed in. Opened with no internet, it goes straight in and shows the **last saved data** (profile and photo, schedule, attendance, grades, alerts) with an amber "You're offline" bar and the time of the last update. If the login expired meanwhile, it signs in again silently once the internet is back.
- Every live screen reconnects and refetches the moment the phone is online again (green "Back online" bar), so data is realtime again without reopening the app.
- Data is saved per user on the phone and wiped on **Sign out**. Writes (marking attendance, sending alerts, USB sync) still need internet.
- Code: `app/lib/core/offline.dart` (`liveStream`, `cachedRows/cachedRow`, `Net`, `Identity`). New packages: `shared_preferences`, `cached_network_image` (run `flutter pub get` / the CI build does it).

## Offline changes for teachers (attendance + scores)
Marking subject attendance and entering class-record scores works without internet: the change is saved on the phone, shown as normal, and sent automatically (oldest first) when the internet is back. The top bar shows how many changes are waiting (tap it for the Sync status sheet).
- **No duplicates:** every change carries an operation id (`X-Op-Id`). The server stores it (`sync_ops`) and a retry returns the stored answer, so nothing is applied or notified twice.
- **Nothing comes back from the dead:** every entry carries the version the teacher saw. If the row was changed since, the server keeps its version; if it was deleted since (date column removed, score cleared, class-record column deleted, student left), it is NOT recreated. Skipped entries are listed under "Not applied" in Sync status.
- Still online-only: deleting a date, adding/deleting record columns, grades, homeroom attendance, no-class alerts, USB sync.
- Signing out with unsent changes asks first; they stay on the phone for that account.

## Feed
Teachers (Feed tab, replaces Subjects; My subjects is now a button in Classes) post text + up to 6 photos with a type, an audience (whole grade level, a section, a subject class, or the homeroom if adviser), and switches for reactions, comments, pin and alerts. Students and parents see posts for their sections, react (hold the React button for more) and open comments on demand. Photos are stored in the existing `pictures` bucket.

## Student enrollment
Sign-up is two short steps (about you, then enrollment). Enrollment: pick the grade level, then
- **Section** - join a section and get every subject the adviser registered there (shown before you confirm), or
- **Subjects** - search the classes offered in that grade (subject, section, teacher) and tick the ones you take. You are placed in the section that covers most of your picks; picks from other sections are saved in `student_subjects`, so those teachers see you in their class lists (attendance, scores, grades, no-class) and your schedule shows those classes too, or
- **Later** - teachers add you to a section.
